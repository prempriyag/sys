# SIR Electoral Roll PDF Extraction

## Overview

Per **SOP TN-VOTER-ANALYTICS-01** (Data Acquisition & Standardization), the system supports:

1. **CSV upload** – Pre-SIR and Post-SIR rolls with columns: `epic_number`, `name`, `relative_name`, `age`, `gender`, `house_no`, `address`, `booth_number`, `constituency_name`.
2. **PDF upload** – ECI-style electoral roll PDFs (e.g. SIR Draft Roll). Data is extracted, standardized (SOP 3.2), and stored in the database.

## PDF Format (ECI Style)

The extractor expects PDFs that contain **tables** with voter rows. Typical column headers (case-insensitive, variants supported):

| Our field       | PDF column examples |
|-----------------|----------------------|
| epic_number     | EPIC No, EPIC No., Elector ID |
| name            | Name, Elector Name |
| relative_name   | Father's Name, Husband's Name, Relative Name |
| age             | Age |
| gender          | Sex, Gender, M/F |
| house_no        | House No, Door No |
| address         | Address, Residence |

- **Constituency** and **Part/Booth number** can appear in the first-page header (e.g. "Assembly Constituency: XYZ", "Part No: 20"). If not present, they can be supplied as form fields when uploading.

## API Endpoints

- `POST /api/upload/pre-sir` – CSV only.
- `POST /api/upload/post-sir` – CSV only.
- `POST /api/upload/pre-sir-pdf` – PDF; form fields: `file` (required), `constituency_name` (optional), `booth_number` (optional).
- `POST /api/upload/post-sir-pdf` – PDF; same form fields as above.

## Standardization (SOP 3.2)

- Text is normalized to **uppercase** and non-alphanumeric characters are removed from address/name for matching.
- Tamil-to-English transliteration is applied via the same normalization service (extend as needed for Lakshmi/Laxmi-style variants).

## Scanned / image-only PDFs (no text layer)

If the PDF has **no selectable text** (e.g. a scanned document), the extractor will get 0 records. In that case:

1. **Use OCR** from the CLI:
   ```bash
   python scripts/extract_pdf_roll.py "path/to/roll.pdf" --ocr --output extracted.csv
   ```
   Requires one of:
   - **Option A (no extra install):** `pip install pymupdf pytesseract easyocr` — if Tesseract is not in PATH, the script automatically uses EasyOCR.
   - **Option B:** Install [Tesseract](https://github.com/UB-Mannheim/tesseract/wiki) and add to PATH, then `pip install pymupdf pytesseract`.

2. Or use a PDF that has a **text layer** (e.g. generated by the ECI roll generator, not a scan).

## Debugging (0 records)

Run with `--debug` to see what the PDF contains:
```bash
python scripts/extract_pdf_roll.py "path/to/roll.pdf" --debug
```
This prints the first page text length, table count, and a preview so you can see the actual format.

## Dependencies

- `pdfplumber` – table/text extraction. Install with: `pip install pdfplumber`.
- For scanned PDFs (--ocr): `pymupdf`, and either `pytesseract`+Tesseract in PATH, or `easyocr` (no system install needed).

## Bulk electoral roll upload (OCR)

The **Bulk electoral roll** feature (`POST /api/upload/bulk-electoral-roll`) detects text vs scanned PDFs and uses:

- **Text PDFs:** pdfminer.six (no extra install).
- **Scanned PDFs:** Tesseract OCR. If Tesseract is not in PATH:
  - **Windows:** Set `TESSERACT_CMD` in the environment to the full path, e.g. `C:\Program Files\Tesseract-OCR\tesseract.exe`. The engine also checks that path automatically if the variable is not set.
  - **Optional fallback:** Install [Tesseract](https://github.com/UB-Mannheim/tesseract/wiki) and add it to PATH, or use EasyOCR: `pip install easyocr` and set `ALLOW_EASYOCR_FALLBACK=true` (or `1`/`yes`) so scanned PDFs are processed when Tesseract is missing.

Invalid or empty PDFs (e.g. "No /Root object!") are skipped; the rest are processed. Check server logs for per-file warnings.

### Data not stored? (troubleshooting)

Data is inserted into the **PostgreSQL** table `voter_data`. If nothing appears in the DB:

1. **Table voter_data missing** – You get a 500 error. Create the table:
   ```bash
   cd backend && python create_sir_tables.py
   ```
   Or run migrations: `alembic upgrade head`.

2. **Column `year` missing** – If the table was created before the constituency/year feature, add the column:
   ```bash
   cd backend && alembic upgrade head
   ```
   Or in PostgreSQL: `ALTER TABLE voter_data ADD COLUMN IF NOT EXISTS year VARCHAR(20);`

3. **Wrong database** – The app uses **PostgreSQL** (see `backend/database/connection.py` and `.env`). Ensure you are querying the same DB (same host, port, database name).

4. **No records extracted** – If all PDFs are scanned and Tesseract (or EasyOCR) fails, `total_found` and `inserted` are 0. Check the API response and server logs (e.g. "OCR extract failed", "tesseract is not installed").

5. **All duplicates** – Existing EPICs are skipped (ON CONFLICT DO NOTHING). So `inserted` can be 0 while `duplicates_skipped` is high. Data is already in the table.

**Verify:** `GET /api/upload/bulk-electoral-roll-count` returns `{ "count": N, "table": "voter_data" }` so you can confirm rows are in the DB.
